---
title: Writing docs
description: Add one short guide for one task.
---

Create an English page under `apps/docs/en/`. Give it a title and a one-sentence description.

## Keep pages focused

Explain what the feature does, what setup it needs, and how the reader can check the result.

Split a topic when it contains separate tasks. For example, file uploads and download access have different steps and deserve separate pages.

## Link related pages

Use existing documentation URLs in Markdown links. Section overview pages should link to their individual guides.

Code examples belong in fenced code blocks. Docs remain Markdown files.

## Review

Open the rendered page, follow its links, and check its navigation and headings. A file parsing successfully does not prove that its instructions work.

See [translated content](/docs/localization/content) when adding another language.
