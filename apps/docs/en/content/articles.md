---
title: Articles and release notes
description: Explain product changes outside the reference docs.
---

Use a blog post to explain an idea or a longer change. Use the changelog to record what shipped and who it affects.

## Blog posts

Keep article source in `apps/blog`. Follow the language-directory convention when adding translated posts.

The workspace does not currently have an article listing or reader route. Add those before treating a Markdown file as published.

## Release notes

Keep release notes in `apps/changelog`. State the visible change, any required action, and whether existing behavior changes.

The changelog also needs publishing routes.

## Keep docs current

When a release changes a feature, update its guide too. Release notes explain the change; documentation explains the current behavior.
